4. Functional Requirements
4.1 Core Modules
Screen State Detection: Continuous polling (every 1-5s) using templates + OCR. States: Village, Attack Search, Battle, Menu, Shop, etc.
Resource Management:
Auto-collect (collectors, cart, clan castle, tombstones).
OCR storage/loot levels; stop/rotate when full.
Army & Training:
Auto-train troops, spells, siege machines based on config.
Handle barracks queues, lab research notifications.
Base Searching & Evaluation:
Set min loot thresholds (Gold/Elixir/DE).
Filter by TH level, dead base indicators (visual: empty core, full collectors via OCR/templates).
Skip/re-search logic.
Attack Automation:
Troop/spell/hero deployment with customizable order, waves, timing.
Smart funneling, red-line accuracy, 2-finger multi-deploy.
Hero abilities at optimal times.
Randomized paths/delays for human-likeness.
Support common strategies (editable via config/JSON).
Upgrades:
Prioritize walls, builders, key buildings when resources allow.
Bulk wall upgrades.2f6279
Clashfarmer
Clan & Social:
Auto-request/donate (keyword-based).
Clan Capital, games, events (future).
Builder Base / Capital: Separate modes or integrated.
4.2 Advanced Features
Humanization Engine: Variable delays (Gaussian distribution), jittered coordinates (±5-10px), random pauses, work-rest scheduler (e.g., 4h on/1h off), mouse-curve simulation if applicable.
Anti-Detection: No fixed patterns; session variability; occasional "human" actions (open chat randomly?); proxy/VPN support for IP rotation.
Multi-Account: Profile switching, emulator instance management.
ML Enhancements (Phase 2): Object detection (YOLO/Roboflow for buildings/troops) for smarter decisions.7dfc08

Logging & Analytics: Detailed logs, stats (loot/hour, success rate), screenshots on errors.
Safety: Auto-stop on suspicious screens (ban warning), resource caps, manual confirm for sensitive actions.

Mobile companion? (Notifications via push).

Visual templates manager (user can add/update images for new game versions).
4.4 Integration & Extensibility
Plugin system for new troops/strategies.
Config files (YAML/JSON) for easy editing.
ADB/emulator abstraction layer for portability.
5. Non-Functional Requirements
Performance: Low CPU (efficient screenshot/processing); handle 24/7 runs.
Reliability: Error recovery (reconnect, retry), crash resilience.
Security: Sandboxed; no unnecessary permissions; user data local-only.
Scalability: Multi-emulator instances.
Compatibility: Latest CoC versions; handle UI changes via robust templates/OCR fallback. Support major emulators.
Accessibility: Configurable resolution (e.g., 1280x720 for consistency).
6. Technical Architecture
Frontend: GUI framework.
Backend: Python core.
OpenCV + NumPy for vision.
EasyOCR / alternatives.
ADB wrapper (pure-python-adb or subprocess).
State machine (e.g., finite state or behavior trees).
Data: Templates folder, configs, logs.
Deployment: Packaged executable (PyInstaller), or APK wrapper for direct device (advanced, requires root/automation apps).
Testing: Unit tests for modules; integration with emulators; simulation of game states.
Update Handling: Game updates break templates—design for easy retraining (user-capturable templates).
